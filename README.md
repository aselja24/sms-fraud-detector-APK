# SMS Fraud Detector

Детектор фишинговых SMS для ТЗ 1 хакатона INAI 2026. Оценивает текст SMS
(русский, кыргызский, кыргызский латиницей, смешанный, в том числе с
обфускацией) и возвращает уровень риска, числовой скор, причины и советы.

```json
{
  "risk": "high",
  "score": 98,
  "reasons": [
    "в тексте указан номер телефона",
    "угроза блокировки номера или карты",
    "просьба сообщить код или пароль",
    "просьба перезвонить или позвонить по номеру"
  ],
  "advice": [
    "Будьте внимательны к номерам в тексте SMS — официальные сервисы обычно используют короткие коды.",
    "Проверьте статус карты/номера только через официальное приложение или горячую линию.",
    "Никогда не сообщайте код из SMS и пароли посторонним, даже «сотрудникам банка».",
    "Не перезванивайте на незнакомый номер из подозрительного SMS."
  ]
}
```

## Установка

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

## Использование

```bash
# Оценить одно SMS
python -m detector.check "Ваша карта заблокирована, сообщите код по номеру +996 555 123456"

# Переобучить модель (веса сохраняются в weights.json)
python train.py data/sms_train.csv --dev data/sms_dev.csv

# Прогнать метрики на размеченном CSV
python evaluate.py data/sms_dev.csv

# Telegram-бот (нужен BOT_TOKEN, см. bot/.env.example)
cp bot/.env.example bot/.env  # и вписать токен
python -m bot.bot

# Тесты
pytest
```

## Как это работает

1. **normalize.py** снимает типичную обфускацию мошенников ДО анализа:
   склеивает "разбитые" пробелами слова (`з а б л о к и р о в а н а` →
   `заблокирована`) и заменяет символы-двойники на кириллицу (`б@нк` →
   `банк`, `с00бщите` → `сообщите`) — но только там, где это действительно
   буква, а не часть настоящего числа (`10до` не трогаем). Также склеивает
   слова, разбитые дефисами/точками (`за-бло-ки-ро-ва-на`, `к.о.д`).
   Чистый транслит (`kartanyz bogottoldu`) не конвертируется.
   Кыргызские буквы приводятся к одному написанию (`translit.py`):
   `жибериңиз` = `жибериниз` (без кыргызской раскладки),
   `Kartaŋyz bögöttöldü` = `kartanyz bogottoldu`.
2. **entities.py** извлекает ссылки (в том числе без `https://`:
   `mbank-kg.com/verify`, `www.optima-login.net`, `bit.ly/...`) и номера
   телефонов (в том числе `0555-12-34-56`) из сырого текста (до нормализации) и проверяет домен
   по белому списку через `hostname` (а не подстрокой — иначе
   `mbank.kg-verify.example` прошёл бы как `mbank.kg`). Домен вне белого
   списка с брендом или имитацией зоны `.kg` (`post-kg.example`) считается
   поддельным.
3. **features.py** собирает 13 бинарных признаков. Корни словаря пишутся
   один раз по-кириллице, а латинские варианты (`жибериңиз` →
   `jiberiniz`, `zhiberiniz`) строятся автоматически, поэтому один корень
   ловит RU, KG, KG без раскладки, транслит и смешанный RU-KG текст. `asks_code` требует
   и слово «код/пароль/CVV», и глагол-просьбу («сообщите», «продиктуйте»,
   «жибериңиз», «soobshite»): само слово «код» есть и в легитимных SMS.
4. **model.py** применяет обученную логистическую регрессию:
   `score = sigmoid(w·x + b) * 100`, уровень — по порогам `LOW=30`,
   `HIGH=65`.
5. **lexicon.py** — словари корней (RU, KG, транслит, немного EN) и для
   каждого признака человеческая причина и совет.

## Признаки и их веса

Веса обучены логистической регрессией на `data/sms_train.csv`
(`C=1.0`, подобран по accuracy на `data/sms_dev.csv` с порогом
`risk == "high"`, при равенстве — по accuracy на train), а не заданы
вручную.

| Признак | Тип | Вес | Описание |
|---|---|---:|---|
| has_phone | доп. | +2.50 | в тексте указан номер телефона |
| fake_brand_domain | доп. | +2.14 | ссылка маскируется под бренд, домен не официальный |
| prize | обяз. | +2.04 | обещание выигрыша/подарка |
| block_threat | обяз. | +1.85 | угроза блокировки/закрытия/взлома |
| asks_code | обяз. | +1.74 | просьба сообщить код/пароль |
| urgency | обяз. | +1.38 | давление срочностью |
| money_transfer | обяз. | +1.36 | просьба перевести/оплатить деньги |
| link_action | доп. | +1.30 | просьба перейти по ссылке и подтвердить/активировать |
| call_back | обяз. | +0.74 | просьба перезвонить |
| foreign_phone | доп. | +0.41 | номер телефона иностранный |
| has_link | обяз. | +0.32 | в сообщении есть ссылка |
| bank_operator | обяз. | +0.08 | упоминание банка/оператора |
| safety_warning | доп. | **−0.61** | в тексте предупреждение «не сообщайте код» |
| intercept | — | −2.98 | — |

`safety_warning` — единственный признак с отрицательным весом: он гасит
риск у легитимных предупреждений («Не переводите деньги незнакомым»,
«Алдамчылардан сак болуңуз»). `bank_operator` почти нулевой: банк и
оператор упоминаются и в мошеннических, и в обычных SMS.

## Метрики

| Набор | Accuracy | Precision (fraud) | Recall (fraud) |
|---|---:|---:|---:|
| train (`sms_train.csv`, 200 примеров) | 1.000 | 1.000 | 1.000 |
| dev (`sms_dev.csv`, 40 примеров) | 1.000 | 1.000 | 1.000 |
| dev, только обфусцированные (8 из 40) | 1.000 | — | — |
| новые формулировки (`tests/test_robustness.py`, 30 SMS) | 0.967 | 1.000 | 0.944 |
| языковые варианты (`tests/test_robustness.py`, 31 SMS) | 1.000 | 1.000 | 1.000 |

Ошибок на train и dev нет. Третий набор — 30 SMS, написанных вручную
с темами, транслитом и обфускацией, которых нет в данных (кэшбэк,
пошлина, «продиктуйте CVV», `utup aldynyz`, `за-бло-ки`, `0555-12-34-56`).
Он показывает, как модель ведёт себя на незнакомых текстах. Четвёртый —
31 SMS на разных вариантах языка: кыргызский без раскладки
(`картаныз боготтолду`), латиница с `ö/ü/ŋ`, смешанные RU-KG
(`ваша карта заблокирована, кодду жибериңиз`), ссылки без `https://`,
несколько английских. Единственная
ошибка — «служба безопасности банка, продиктуйте код» без телефона,
ссылки и угрозы: одной просьбы кода по train-весам мало для `high`
(получается `low`).

## Сравнение методов

| Признаки | dev Accuracy | dev Recall | новые SMS Accuracy | новые SMS Precision | новые SMS Recall |
|---|---:|---:|---:|---:|---:|
| только 8 обязательных по ТЗ | 1.000 | 1.000 | 0.869 | 0.875 | 0.921 |
| все 13 (8 + 5 дополнительных) | 1.000 | 1.000 | **0.984** | **1.000** | **0.974** |

На открытом `dev` оба варианта показывают 100%: этот набор хорошо
разделим уже по 8 обязательным признакам. Разница видна на незнакомых
текстах (61 SMS из `tests/test_robustness.py`) — там дополнительные 5
признаков поднимают accuracy с 87% до 98% и убирают все ложные
срабатывания:

- `fake_brand_domain` и `has_link` вместе отличают фишинговую ссылку от
  обычной (ссылки есть и у легитимных SMS — оператор, банк, доставка);
- `has_phone`/`foreign_phone` ловят случаи без явных слов "перезвоните"
  (например, просто номер для перевода денег);
- `safety_warning` — противовес для легитимных предупреждений
  («не переводите деньги», «сак болуңуз»), где есть те же слова, что и
  в мошеннических SMS.

## Структура проекта

```
detector/
  config.py      — белый список доменов, бренды, пороги LOW/HIGH
  lexicon.py      — словари корней (RU/KY/транслит), причины, советы
  entities.py     — поиск ссылок/телефонов, проверка белого списка и подделок брендов
  normalize.py    — снятие обфускации
  translit.py     — единое написание ө/ү/ң, транслит корней в латиницу
  features.py     — 13 признаков в фиксированном порядке
  model.py        — предсказание скора, уровень риска, причины
  check.py        — check(text) + CLI
train.py          — обучение логистической регрессии
evaluate.py        — метрики на размеченном CSV
tests/             — pytest
bot/                — Telegram-бот (бонус)
data/               — данные организаторов (не изменяются)
```

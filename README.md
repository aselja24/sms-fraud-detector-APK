# SMS Fraud Detector

Детектор фишинговых SMS для ТЗ 1 хакатона INAI 2026. Оценивает текст SMS
(русский, кыргызский, кыргызский латиницей, смешанный, в том числе с
обфускацией) и возвращает уровень риска, числовой скор, причины и советы.

```json
{
  "risk": "high",
  "score": 98,
  "reasons": [
    "в тексте указан номер телефона",
    "угроза блокировки номера или карты",
    "просьба сообщить код или пароль",
    "просьба перезвонить или позвонить по номеру"
  ],
  "advice": [
    "Будьте внимательны к номерам в тексте SMS — официальные сервисы обычно используют короткие коды.",
    "Проверьте статус карты/номера только через официальное приложение или горячую линию.",
    "Никогда не сообщайте код из SMS и пароли посторонним, даже «сотрудникам банка».",
    "Не перезванивайте на незнакомый номер из подозрительного SMS."
  ]
}
```

## Как это работает

1. **normalize.py** снимает типичную обфускацию мошенников ДО анализа:
   склеивает "разбитые" пробелами слова (`з а б л о к и р о в а н а` →
   `заблокирована`) и заменяет символы-двойники на кириллицу (`б@нк` →
   `банк`, `с00бщите` → `сообщите`) — но только там, где это действительно
   буква, а не часть настоящего числа (`10до` не трогаем). Также склеивает
   слова, разбитые дефисами/точками (`за-бло-ки-ро-ва-на`, `к.о.д`).
   Чистый транслит (`kartanyz bogottoldu`) не конвертируется.
   Кыргызские буквы приводятся к одному написанию (`translit.py`):
   `жибериңиз` = `жибериниз` (без кыргызской раскладки),
   `Kartaŋyz bögöttöldü` = `kartanyz bogottoldu`.
2. **entities.py** извлекает ссылки (в том числе без `https://`, с
   кириллицей в названии и в виде `hxxps://`: `mbank-kg.com/verify`,
   `www.optima-login.net`, `bit.ly/...`) и номера телефонов (в том числе
   `0555-12-34-56`) из сырого текста (до нормализации) и проверяет домен
   по белому списку через `hostname` (а не подстрокой — иначе
   `mbank.kg-verify.example` прошёл бы как `mbank.kg`).
   **links.py** разбирает каждый адрес: считает его «скелет» (кириллица,
   цифры `0/1/3/5`, заглавная `I` и `rn` заменяются на похожие латинские
   буквы) и сравнивает с белым списком и брендами. `mbаnk.kg` с
   кириллической «а» даёт скелет `mbank.kg`, `0ptima-bank.info` — `optima`,
   `teIegram` — `telegram`: адрес выдаёт себя за настоящий. Такая ссылка —
   подделка, в ответе называется подменённый символ и настоящий сайт.
   Обход, который раньше пропускал ссылку, закрыт так: зона может быть
   написана кириллицей (`mbank.кг`), адрес может содержать невидимые
   символы (`mb<нулевой пробел>ank.kg`) или «[.]» вместо точки
   (`mbank[.]kg`), буквы могут быть полноширинными (`ｍbank.kg`), а
   адрес целиком из кириллицы выдаёт себя за бренд (`бакай.кг`). Невидимые
   символы и «[.]» снимаются перед поиском ссылки и сами по себе считаются
   признаком подделки: настоящее SMS их не использует.
   Анализ идёт по сырому тексту и с исходным регистром: `normalize()`
   переводит латиницу в кириллицу (для словарей) и не может превратить
   подделку в официальный домен. Домен вне белого списка с брендом,
   фишинговым словом (`confirm`, `support`, `help`, `verify`...), зоной
   `.xyz/.top/.info` или имитацией `.kg` (`post-kg.example`) считается
   поддельным. Целиком кириллические адреса (`ак-тилек.kg`) подделкой не
   считаются.
3. **features.py** собирает 14 бинарных признаков. Корни словаря пишутся
   один раз по-кириллице, а латинские варианты (`жибериңиз` →
   `jiberiniz`, `zhiberiniz`) строятся автоматически, поэтому один корень
   ловит RU, KG, KG без раскладки, транслит и смешанный RU-KG текст.
   `asks_code` требует и слово «код/пароль/CVV/данные карты/паспорт», и
   глагол-просьбу («сообщите», «введите», «жибериңиз», «жибер»,
   «soobshite»): само слово «код» есть и в легитимных SMS. Срок в цифрах
   («через 30 минут», «10 мүнөт ичинде») тоже считается срочностью.
4. **model.py** применяет обученную логистическую регрессию:
   `score = sigmoid(w·x + b) * 100`, уровень — по порогам `LOW=30`,
   `HIGH=65`.
5. **rules.py** — жёсткие правила поверх модели (см. ниже): нижняя граница
   score — 80 для `high` и 30 для `medium`.
6. **text_model.py** — обучаемый текстовый слой (см. «Как модель учится на
   новых данных»): символьные n-граммы + логистическая регрессия. Второе
   мнение для SMS без ссылок, которые модель оценила как `medium`.
7. **lexicon.py** — словари корней (RU, KG, транслит, немного EN) и для
   каждого признака человеческая причина и совет.

## Признаки и их веса

Веса обучены логистической регрессией только на `data/sms_train.csv`
(`C=1.0`, подобран по accuracy на `data/sms_dev.csv` с порогом
`risk == "high"`, при равенстве — по accuracy на train), а не заданы
вручную.

| Признак | Тип | Вес | Описание |
|---|---|---:|---|
| has_phone | доп. | +2.45 | в тексте указан номер телефона |
| fake_brand_domain | доп. | +2.12 | домен не официальный: бренд в чужом домене или зона .xyz/.top/.info |
| prize | обяз. | +2.06 | обещание выигрыша/подарка/выплаты |
| action_request | доп. | +1.67 | любая просьба: передать данные, оплатить, позвонить, перейти по ссылке |
| block_threat | обяз. | +1.39 | угроза блокировки или «проблема со счётом/посылкой» |
| asks_code | обяз. | +1.33 | просьба сообщить код/пароль/данные карты |
| urgency | обяз. | +1.17 | давление срочностью |
| link_action | доп. | +0.83 | просьба перейти по ссылке и подтвердить/активировать |
| call_back | обяз. | +0.67 | просьба перезвонить |
| foreign_phone | доп. | +0.43 | номер телефона иностранный |
| bank_operator | обяз. | +0.32 | упоминание банка/оператора |
| money_transfer | обяз. | +0.21 | просьба перевести/оплатить деньги |
| has_link | обяз. | +0.11 | в сообщении есть ссылка |
| safety_warning | доп. | **−0.49** | в тексте предупреждение «не сообщайте код» |
| intercept | — | −3.56 | — |

`safety_warning` — единственный признак с отрицательным весом: он гасит
риск у легитимных предупреждений («Не переводите деньги незнакомым»,
«Алдамчылардан сак болуңуз»). `action_request` объединяет четыре частные
просьбы (`asks_code`, `money_transfer`, `call_back`, `link_action`): в
train почти у каждого мошеннического SMS есть какая-то просьба, а у
обычных — редко, и общий признак получает вес целиком, а не делит его на
четыре части. Поэтому у `money_transfer` вес теперь маленький — его
вклад в основном идёт через `action_request`.

## Правила поверх модели

В train почти у каждого мошеннического SMS есть номер телефона или ссылка
с явным брендом, поэтому модель ставит `high` только при 3+ признаках.
Мошенничество вида «повод + просьба» без телефона («Для отмены перевода
назовите оператору код из SMS») и ссылки-подделки, где улика — сам адрес
(`mbаnk.kg`), она оценивает слишком низко: таких примеров в train просто
нет, а признак «подмена символов» в train всегда равен 0 и получил бы вес
0. `detector/rules.py` не меняет обученные веса, а только поднимает нижнюю
границу score для сценариев, которые не встречаются в легитимных SMS:

| Правило | Условие | Нижняя граница |
|---|---|---:|
| `link_spoof` | в адресе ссылки подменены символы (`links.py`) | 80 (`high`) |
| `secret_request` | просят код, пароль, CVV или данные карты | 80 (`high`) |
| `money_with_pretext` | просят перевести/оплатить деньги + угроза, выигрыш или срочность | 80 (`high`) |
| `brand_link_with_cue` | ссылка под видом бренда (или бренд назван в тексте, а ссылка ведёт на чужой адрес) + давление, просьба, сумма денег («150 000 сом», «100 ГБ», «0%») или просьба о деньгах | 80 (`high`) |
| `easy_money` | «лёгкий заработок» («от 5000 сом в день», «онлайн жумуш») + ссылка на мессенджер (`wa.me`, `t.me`) или неофициальный сайт | 80 (`high`) |
| `prize_with_link` | «вы выиграли» (сильные корни: выиграл, приз, розыгрыш, утуп алдыңыз, белек…) + любая ссылка, в том числе официальная | 80 (`high`) |
| `brand_link` | ссылка под видом бренда, но без давления, просьбы и суммы («Подробности: mbank-info.net») | 30 (`medium`) |
| `unofficial_click` | неофициальная ссылка + «откройте/нажмите/перейдите» | 30 (`medium`) |
| `brand_mismatch` | в SMS назван бренд, а неофициальная ссылка ведёт на другой адрес | 30 (`medium`) |

Официальность ссылки риск не снижает. Имя домена, почти совпадающее с брендом (`eline.kg` вместо `beeline.kg`, расстояние 2), считается имитацией бренда. Несовпадение бренда с официальной ссылкой (Beeline в тексте, `mbank.kg` в ссылке) сам по себе риск не поднимает, потому что операторы ссылаются друг на друга, но в ответе объясняется, если SMS уже подозрительно.

Граница 80, а не 65, чтобы ответ не выглядел «на грани». Так же, как белый
список доменов, это экспертное знание, которое из 200 обучающих SMS не
выучить. Ложных срабатываний правила не дают ни на одном наборе. Сработавшее
правило идёт первой причиной и первым советом в ответе; для подмены символов
там указано, какой символ подменён, и настоящий сайт бренда
(«Настоящий сайт — mbank.kg»). Подсказка есть только для доменов, в которых
уверены (список ТЗ и настоящие домены из учебных SMS).

Метрики посчитаны для итогового варианта: модель + правила. В репозитории
остались только файлы ТЗ (`data/sms_train.csv` — на нём обучена модель,
`data/sms_dev.csv` — по нему подобран `C`); внешние наборы

для проверки и в репозиторий не входят. Любой такой CSV (`id,text,label`)
можно проверить командой `python evaluate.py путь/к/файлу.csv`.

**Регрессионный набор `tests/sms_hard.csv`** — 63 трудных случая с колонкой
`expected_risk` (допустимые уровни, например `low|medium`): подмена символов
в адресе (кириллица, цифры, `I` вместо `l`, `rn` вместо `m`, punycode),
бренд в чужом домене, поддомен-обманка (`mbank.kg.secure-login.net`),
`mbank.kg@evil-login.net`, настоящие домены с угрозой в тексте, короткие SMS
без телефона. Ожидания записаны по смыслу, а не по ответу модели; до
правок ссылок код проваливал 19 из 41 случая (9 подделок получали `low`), после —
ни одного. После правок с кириллической зоной, невидимыми символами, «[.]»,
полноширинными буквами и кириллическими брендами там добавлены ещё 8 строк,
и все они проходят. Тест `tests/test_hard.py` запускается вместе со всеми. Набор не
используется для обучения и подбора словаря — это защита от поломок при
будущих правках, а не оценка качества.

Ошибок на train и dev нет. Третий набор — 30 SMS, написанных вручную
с темами, транслитом и обфускацией, которых нет в данных (кэшбэк,
пошлина, «продиктуйте CVV», `utup aldynyz`, `за-бло-ки`, `0555-12-34-56`).
Четвёртый — 31 SMS на разных вариантах языка: кыргызский без раскладки
(`картаныз боготтолду`), латиница с `ö/ü/ŋ`, смешанные RU-KG
(`ваша карта заблокирована, кодду жибериңиз`), ссылки без `https://`,
несколько английских.

Внешние наборы (`sms_phishing_test_*.csv`) не из архива организаторов.
Словарь расширялся с оглядкой на ошибки в наборах из 120 и 140 SMS,
поэтому оценки на них оптимистичные; набор `sms_phishing_test_2.csv`
появился после этого, и словарь под него не подбирался — правила
подняли на нём accuracy с 0.723 до 0.899. В наборе из 140 SMS есть
настоящие домены банков (`megacom.kg`, `optima24.kg`, `bakai.kg`) — они
добавлены в белый список, иначе считались подделкой бренда; фишинговые
ссылки там в зонах `.xyz`, `.top`, `.info` — такие зоны теперь считаются
подозрительными; сценарий «с вашего счёта списывают деньги — пришлите
код, чтобы отменить» («алынууда», «жокко чыгаруу», «кирүү аракети»)
добавлен в угрозы. Набор из 120 SMS
устроен иначе: в мошеннических SMS почти нет номеров и
ссылок, только «повод + просьба» («Банк обнаружил проблему, переведите
деньги на безопасный счёт»). До доработки словаря на нём было
accuracy 0.633 / recall 0.267.

**Честная оценка.** Цифры 1.000 на train, dev и наборах, по ошибкам
которых дописывался словарь, — настроечные. Проверка без утечки — набор,
который ни разу не использовался при доработке:

| Проверка | Accuracy | Precision | Recall |
|---|---:|---:|---:|
| отложенная половина внешнего набора (52 SMS, другие схемы), до доработки | 0.692 | 1.000 | 0.385 |
| та же половина после доработки по первой половине | 0.846 | 1.000 | 0.692 |
| `phishing_sms_multilingual.csv` (50 SMS), итоговая версия | 0.920 | 0.955 | 0.875 |

Доработки делались только общего характера: зоны `.invalid`/`.test` как
ссылки (как `.example`), глаголы действия рядом со ссылкой, «служебные»
слова в домене (`payment`, `delivery`, `notice`, `account`), правило
«поддельный домен + сумма денег», «лёгкий заработок», госвыплаты и долги.
Модель при этом переобучалась только на `sms_train.csv` — веса не
изменились. Проверить самостоятельно: переобучить с нуля
(`python train.py`) и прогнать `evaluate.py` на любом CSV из `data/`.

**Ограничение.** Мошенничество новых видов, которых нет ни в train, ни в
словаре (подписки, «возврат средств», вакансии без суммы), детектор
пропускает: score остаётся `low` или `medium`. Обученный слой
(`text_model.py`) закрывает это по мере накопления отметок из бота.

## Как модель учится на новых данных

Основная модель — 14 признаков по словарю. Новые данные могут только
перевесить эти признаки, но не научить её новым словам: каждую новую
формулировку мошенников пришлось бы вписывать в `lexicon.py` вручную.
Поэтому есть второй, обучаемый слой — `detector/text_model.py`:

- текст после `normalize()` режется на куски по 2–5 символов внутри слов
  (как `TfidfVectorizer(analyzer="char_wb")`), так ловятся словоформы и
  транслит; на них обучается логистическая регрессия;
- модель хранится в `text_model.json` (n-грамма → idf и вес), применяется
  на чистом Python — боту и `check()` sklearn не нужен; результат совпадает
  со sklearn до 10⁻⁶;
- в `check()` слой — «второе мнение»: поднимает `medium` до `high` только
  для SMS **без ссылок** и только когда уверен (вероятность ≥ 0.6). Ссылки
  точнее разбирает `links.py`, а одному текстовому слою на 200 шаблонных
  SMS из train доверять нельзя: обученный только на train, он даёт на
  внешних SMS 10–19 ложных срабатываний. В причине — слова, которые
  повлияли: «текст похож на мошеннические SMS: «башка», «картага»».

**Откуда новые данные.** Под каждым ответом Telegram-бота есть кнопки
«🚨 Это мошенничество» / «✅ Не мошенничество»; отметки пишутся в
`data/feedback/feedback.csv` (только текст, отметка, оценка и время — без
id пользователя; папка в `.gitignore`, потому что в SMS бывают личные
данные). Подойдёт и любой CSV с колонками `text,label`.

**Дообучение:** `python train.py --extra data/feedback/feedback.csv`.
- Новые данные идут только в текстовый слой; `weights.json` остаётся
  обученным на `sms_train.csv` (ТЗ). Флаг `--retrain-features` добавляет
  их и в признаки — но проверка показала, что перевешивание признаков на
  внешних SMS ломает трудные случаи (официальная ссылка + угроза
  становится `high`), а дообучение одного текстового слоя — нет.
- Строки, совпадающие с dev или `sms_hard.csv`, выбрасываются (иначе
  проверка была бы нечестной).
- Перед сохранением весь `check()` с новыми моделями прогоняется на dev и
  `sms_hard.csv` и сравнивается с текущими файлами; если стало хуже —
  файлы не перезаписываются (`--force` — сохранить всё равно).
- В обоих файлах записано, на чём они обучены (`trained_on`). Для сдачи по
  ТЗ — запускайте `python train.py` без `--extra`.

Проверка, что это работает (дообучение на одном внешнем наборе, оценка на
30 SMS, написанных до всех правок словаря и ни разу не использованных для
подбора):

| Чем дообучен текстовый слой | отложенные 30 SMS | `sms_hard` |
|---|---:|---:|
| только train | 0.933 | 1.000 |
| train + `sms_phishing_test_2.csv`, признаки тоже перевешены (`--retrain-features`) | 1.000 | 0.983 — проверка качества не даст сохранить |
| train + `sms_phishing_test_2.csv`, признаки по ТЗ (по умолчанию) | 0.933 | 1.000 |

То есть больше всего выигрывают перевешенные признаки, но ценой трудных
случаев; безопасный путь по умолчанию — текстовый слой, и его польза растёт
по мере того, как копятся отметки из бота.

## Сравнение методов

| Вариант | dev Acc / Recall | 61 новое SMS: Acc / P / R | внешние 120: Acc / P / R | внешние 140: Acc / P / R |
|---|---:|---:|---:|---:|
| только 8 обязательных по ТЗ (C=30) | 0.950 / 0.900 | 0.869 / 0.895 / 0.895 | 0.983 / 1.000 / 0.967 | 0.964 / 0.945 / 0.986 |
| 13 (8 + 5 дополнительных) | 1.000 / 1.000 | 0.967 / 1.000 / 0.947 | 0.833 / 1.000 / 0.667 | 0.986 / 1.000 / 0.971 |
| 14 (+ `action_request`), без правил | **1.000 / 1.000** | **0.984 / 1.000 / 0.974** | 0.858 / 1.000 / 0.717 | **1.000 / 1.000 / 1.000** |
| 14, обучение на `sms_train_augmented_2.csv` (C=3) | 1.000 / 1.000 | 0.984 / 1.000 / 0.974 | 0.842 / 1.000 / 0.683 | 0.993 / 1.000 / 0.986 |
| **14 + правила (`rules.py`)** — итоговая | **1.000 / 1.000** | **1.000 / 1.000 / 1.000** | **0.983 / 1.000 / 0.967** | **1.000 / 1.000 / 1.000** |

Все строки, кроме четвёртой, обучены на `sms_train.csv` (200 SMS).
Четвёртая — на `sms_train_augmented_2.csv` (файл после эксперимента удалён
из репозитория): те же 200 SMS плюс по две обфусцированные копии каждого. Аугментация ничего не даёт: обфускацию и так снимает
`normalize.py`, а новых видов мошенничества в копиях нет. Поэтому
итоговые веса обучены только на `sms_train.csv`, как требует ТЗ.

Для каждого варианта `C` подбирался одинаково — по accuracy на dev
(правила при подборе не участвуют). Модель на 8 признаках неплохо ловит
SMS без телефонов, но хуже на dev, которому по условиям соответствует
скрытый набор, и даёт ложные срабатывания. Итоговый вариант — 14
признаков + правила: лучший или равный результат на всех наборах и ни
одного ложного срабатывания. На `sms_phishing_test_2.csv` без правил
accuracy 0.723, с правилами — 0.899.

- `fake_brand_domain` и `has_link` вместе отличают фишинговую ссылку от
  обычной (ссылки есть и у легитимных SMS — оператор, банк, доставка);
- `has_phone`/`foreign_phone` ловят случаи без явных слов "перезвоните"
  (например, просто номер для перевода денег);
- `safety_warning` — противовес для легитимных предупреждений
  («не переводите деньги», «сак болуңуз»), где есть те же слова, что и
  в мошеннических SMS;
- `action_request` — любая просьба что-то сделать (см. выше).

## Telegram-бот (SakBol)

`python -m bot.bot` (токен — `BOT_TOKEN` в `bot/.env`).

Главное меню «Что вас беспокоит?» (`/start`, `/menu`, кнопки под сообщением и внизу экрана):
- **💬 Проверить подозрительное SMS** — текст или скриншот, ответ `check()`.
- **🔗 Проверить ссылку** — разбор адреса через `links.py`: подмена букв,
  punycode, «почти как у бренда», настоящий сайт бренда.
- **⚠️ Я уже попался на уловку** — пошаговая помощь в зависимости от того,
  что успел сделать человек (открыл ссылку, ввёл телефон, пароль, код,
  перевёл деньги), контакты банков и инструкция, если установлено APK или
  приложение удалённого доступа.

- **Текст или скриншот SMS.** Скриншот читается через Tesseract
  (`bot/ocr.py`). Нужно установить сам Tesseract с языками
  (`brew install tesseract tesseract-lang` на macOS,
  `apt install tesseract-ocr tesseract-ocr-rus tesseract-ocr-kir` на Ubuntu)
  и `pip install -r requirements.txt`. Без них бот отвечает, что скриншоты
  пока недоступны. По картинке нельзя отличить кириллическую «а» от
  латинской, поэтому в распознанных ссылках похожие буквы приводятся к
  латинице — иначе распознавание само создавало бы ложные «подмены»; бот
  предупреждает, что адрес на скриншоте нужно проверить глазами.
- **Кыргызча / русский** (`/lang`, по умолчанию — язык Telegram).
  `check()` отвечает по-русски, бот переводит причины и советы сам
  (`bot/i18n.py`); тест проверяет, что у каждого признака и правила есть
  кыргызский перевод. Перевод стоит проверить носителю языка.
- **«🚨 Это мошенничество» / «✅ Не мошенничество»** — отметки для
  дообучения (`data/feedback/feedback.csv`, см. «Как модель учится на новых
  данных»).
- **«📤 Предупредить близких»** (для `medium`/`high`) — открывает
  стандартное окно Telegram «Поделиться»: пользователь сам выбирает, кому
  переслать короткое предупреждение. Адреса в нём записаны как
  `mbаnk[.]kg`, чтобы родственник случайно не открыл ссылку мошенников.

Рассылки по контактам нет и не будет: бот не видит контакты пользователя и
по правилам Telegram может писать только тем, кто сам его запустил, а
сообщения людям без их согласия — это спам.

## Симуляция SakBol Gateway (безопасные ссылки у оператора)

Демо того, как детектор мог бы работать в сети оператора: опасная ссылка
не доходит до абонента как есть, а заменяется на ссылку шлюза. При переходе
открывается страница-стоп, и сайт мошенников не загружается.

```bash
python gateway_server.py          # пульт оператора: http://127.0.0.1:8000
```

Чтобы открыть подменённую ссылку с телефона в той же Wi-Fi сети:
`python gateway_server.py --host 0.0.0.0 --public-url http://<IP-компьютера>:8000`.

- **Пульт** (`/`): входящее SMS, примеры (фейк Beeline/MBANK, кириллическая «а»,
  невидимый символ, адрес кириллицей, похожий домен, «[.]»), SMS «как увидит
  абонент», решение по каждой ссылке и причины, счётчики и реестр перехватов.
- **Страница-стоп** (`/x/<токен>`, кыргызча/русский): почему ссылка опасна,
  адрес мошенников в некликабельном виде (`mbank[.]kg-verify[.]example`),
  что делать и кнопка на настоящий сайт бренда, если он известен.
- **Отправитель** — то, что видит оператор, но не видит бот. Поле
  «Отправитель» на пульте (`sender` в API):
  - SMS от имени банка или оператора с обычного номера (`+996 555 …`) → high:
    они пишут с буквенного имени (MBANK) или короткого номера;
  - в буквенном имени смешаны алфавиты (`MBАNK` с кириллической «А») → high;
  - иностранный номер и ссылка → medium.

  `check()` не меняется: шлюз отдаёт свой итог отдельно (`gateway_risk`,
  `gateway_score`, `gateway_reasons`), и ссылки подменяются по нему.
- **Поток SMS** — прогон набора через шлюз с живой лентой и сводкой:
  сколько ссылок в честных SMS тронуто зря, сколько ссылок мошенников
  обезврежено, сколько официальных оставлено. Список наборов берётся из
  папки `data/` автоматически — любой CSV с колонками `text` и `label`
  (сейчас там `sms_train` и `sms_dev`); положили в `data/` свой набор — он
  появился в списке после обновления страницы. На dev: 0 из 9 ссылок в
  честных SMS тронуто, 9 из 9 ссылок мошенников обезврежено.
- **Оформление**: тёмная верхняя панель, карточки «Проверить SMS» → «Путь SMS
  через шлюз» (пришло в сеть → шлюз → доставлено абоненту, ссылки и причины)
  → «Поток SMS» → «Реестр перехватов». Страница работает без интернета:
  внешних шрифтов и скриптов нет.
- **API**: `POST /api/check` `{"text": "...", "sender": "MBANK"}`,
  `GET /api/datasets`, `POST /api/stream` `{"dataset": "sms_dev"}`,
  `GET /api/records`, `POST /api/reset`.

Что подменяется (`detector/gateway.py`): ссылки с подменой или спрятанными
символами, ссылки под видом бренда и «почти как у бренда», а в SMS с риском
medium/high — любые неофициальные ссылки. Официальные адреса из белого
списка не трогаются, даже если текст SMS мошеннический. Ссылки находятся тем
же анализом, что и в `check()`, и заменяются по их позициям в исходном тексте,
поэтому `mb<нулевой пробел>ank.kg` и `mbank [.] kg` действительно исчезают
из SMS. Реестр хранит только адрес и причины, текст SMS не сохраняется.
Всё, что пришло из SMS, выводится в HTML экранированным, а страницы
отдаются с Content-Security-Policy.

## Структура проекта

```
detector/
  config.py      — белый список доменов, бренды, пороги LOW/HIGH
  lexicon.py      — словари корней (RU/KY/транслит), причины, советы
  entities.py     — поиск ссылок/телефонов, белый список домена
  links.py        — анализ ссылок: подмена символов (скелет адреса), смешанные алфавиты, punycode, скрытые символы
  homoglyphs.py   — таблицы похожих символов, транслитерации и доменных зон на кириллице
  normalize.py    — снятие обфускации
  translit.py     — единое написание ө/ү/ң, транслит корней в латиницу
  features.py     — 14 признаков в фиксированном порядке
  model.py        — предсказание скора, уровень риска, причины
  text_model.py   — обучаемый текстовый слой (n-граммы + LR), инференс без sklearn
  rules.py        — жёсткие правила поверх модели (подмена в ссылке, просьба кода, деньги + повод)
  gateway.py      — симуляция шлюза безопасных ссылок: подмена опасных ссылок в SMS
  check.py        — check(text) + CLI
gateway_server.py — веб-демо шлюза SakBol (пульт оператора + страница-стоп)
train.py          — обучение (признаки по ТЗ + текстовый слой, --extra, проверка качества)
weights.json      — веса 14 признаков; text_model.json — текстовый слой
evaluate.py        — метрики на размеченном CSV
tests/             — pytest (и регрессионный набор sms_hard.csv)
bot/                — Telegram-бот (бонус): bot.py, i18n.py (кыргызча/русский), ocr.py (скриншоты), feedback.py (отметки)
data/
  sms_train.csv     — обучающий набор ТЗ: на нём обучены weights.json и text_model.json
  sms_dev.csv       — открытый набор ТЗ: подбор C и проверка
  README_RU.md, CLARIFICATIONS_RU.md — описание данных от организаторов
  feedback/         — отметки из бота (в .gitignore)
tests/sms_hard.csv  — наш регрессионный набор трудных случаев (часть тестов)
```

# SMS Fraud Detector

Детектор фишинговых SMS для ТЗ 1 хакатона INAI 2026. Оценивает текст SMS
(русский, кыргызский, кыргызский латиницей, смешанный, в том числе с
обфускацией) и возвращает уровень риска, числовой скор, причины и советы.

```json
{
  "risk": "high",
  "score": 98,
  "reasons": [
    "в тексте указан номер телефона",
    "угроза блокировки номера или карты",
    "просьба сообщить код или пароль",
    "просьба перезвонить или позвонить по номеру"
  ],
  "advice": [
    "Будьте внимательны к номерам в тексте SMS — официальные сервисы обычно используют короткие коды.",
    "Проверьте статус карты/номера только через официальное приложение или горячую линию.",
    "Никогда не сообщайте код из SMS и пароли посторонним, даже «сотрудникам банка».",
    "Не перезванивайте на незнакомый номер из подозрительного SMS."
  ]
}
```

## Установка

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

## Использование

```bash
# Оценить одно SMS
python -m detector.check "Ваша карта заблокирована, сообщите код по номеру +996 555 123456"

# Переобучить модель (веса сохраняются в weights.json)
python train.py data/sms_train.csv --dev data/sms_dev.csv

# Прогнать метрики на размеченном CSV
python evaluate.py data/sms_dev.csv

# Telegram-бот (нужен BOT_TOKEN, см. bot/.env.example)
cp bot/.env.example bot/.env  # и вписать токен
python -m bot.bot

# Тесты
pytest
```

## Как это работает

1. **normalize.py** снимает типичную обфускацию мошенников ДО анализа:
   склеивает "разбитые" пробелами слова (`з а б л о к и р о в а н а` →
   `заблокирована`) и заменяет символы-двойники на кириллицу (`б@нк` →
   `банк`, `с00бщите` → `сообщите`) — но только там, где это действительно
   буква, а не часть настоящего числа (`10до` не трогаем). Также склеивает
   слова, разбитые дефисами/точками (`за-бло-ки-ро-ва-на`, `к.о.д`).
   Чистый транслит (`kartanyz bogottoldu`) не конвертируется.
   Кыргызские буквы приводятся к одному написанию (`translit.py`):
   `жибериңиз` = `жибериниз` (без кыргызской раскладки),
   `Kartaŋyz bögöttöldü` = `kartanyz bogottoldu`.
2. **entities.py** извлекает ссылки (в том числе без `https://`:
   `mbank-kg.com/verify`, `www.optima-login.net`, `bit.ly/...`) и номера
   телефонов (в том числе `0555-12-34-56`) из сырого текста (до нормализации) и проверяет домен
   по белому списку через `hostname` (а не подстрокой — иначе
   `mbank.kg-verify.example` прошёл бы как `mbank.kg`). Домен вне белого
   списка с брендом или имитацией зоны `.kg` (`post-kg.example`) считается
   поддельным.
3. **features.py** собирает 14 бинарных признаков. Корни словаря пишутся
   один раз по-кириллице, а латинские варианты (`жибериңиз` →
   `jiberiniz`, `zhiberiniz`) строятся автоматически, поэтому один корень
   ловит RU, KG, KG без раскладки, транслит и смешанный RU-KG текст.
   `asks_code` требует и слово «код/пароль/CVV/данные карты/паспорт», и
   глагол-просьбу («сообщите», «введите», «жибериңиз», «жибер»,
   «soobshite»): само слово «код» есть и в легитимных SMS. Срок в цифрах
   («через 30 минут», «10 мүнөт ичинде») тоже считается срочностью.
4. **model.py** применяет обученную логистическую регрессию:
   `score = sigmoid(w·x + b) * 100`, уровень — по порогам `LOW=30`,
   `HIGH=65`.
5. **rules.py** — два жёстких правила поверх модели (см. ниже): просьба
   передать код/пароль/данные карты или просьба о деньгах вместе с
   угрозой/выигрышем/срочностью сразу дают `high` (`score = max(score, 65)`).
6. **lexicon.py** — словари корней (RU, KG, транслит, немного EN) и для
   каждого признака человеческая причина и совет.

## Признаки и их веса

Веса обучены логистической регрессией только на `data/sms_train.csv`
(`C=1.0`, подобран по accuracy на `data/sms_dev.csv` с порогом
`risk == "high"`, при равенстве — по accuracy на train), а не заданы
вручную.

| Признак | Тип | Вес | Описание |
|---|---|---:|---|
| has_phone | доп. | +2.45 | в тексте указан номер телефона |
| fake_brand_domain | доп. | +2.12 | домен не официальный: бренд в чужом домене или зона .xyz/.top/.info |
| prize | обяз. | +2.06 | обещание выигрыша/подарка/выплаты |
| action_request | доп. | +1.67 | любая просьба: передать данные, оплатить, позвонить, перейти по ссылке |
| block_threat | обяз. | +1.39 | угроза блокировки или «проблема со счётом/посылкой» |
| asks_code | обяз. | +1.33 | просьба сообщить код/пароль/данные карты |
| urgency | обяз. | +1.17 | давление срочностью |
| link_action | доп. | +0.83 | просьба перейти по ссылке и подтвердить/активировать |
| call_back | обяз. | +0.67 | просьба перезвонить |
| foreign_phone | доп. | +0.43 | номер телефона иностранный |
| bank_operator | обяз. | +0.32 | упоминание банка/оператора |
| money_transfer | обяз. | +0.21 | просьба перевести/оплатить деньги |
| has_link | обяз. | +0.11 | в сообщении есть ссылка |
| safety_warning | доп. | **−0.49** | в тексте предупреждение «не сообщайте код» |
| intercept | — | −3.56 | — |

`safety_warning` — единственный признак с отрицательным весом: он гасит
риск у легитимных предупреждений («Не переводите деньги незнакомым»,
«Алдамчылардан сак болуңуз»). `action_request` объединяет четыре частные
просьбы (`asks_code`, `money_transfer`, `call_back`, `link_action`): в
train почти у каждого мошеннического SMS есть какая-то просьба, а у
обычных — редко, и общий признак получает вес целиком, а не делит его на
четыре части. Поэтому у `money_transfer` вес теперь маленький — его
вклад в основном идёт через `action_request`.

## Правила поверх модели

В train почти у каждого мошеннического SMS есть номер телефона или ссылка,
поэтому модель ставит `high` только при 3+ признаках. Мошенничество вида
«повод + просьба» без телефона и ссылки («Для отмены перевода назовите
оператору код из SMS») она оценивает как `medium` — таких примеров в
train просто нет. `detector/rules.py` не меняет обученные веса, а только
поднимает риск до `high` в двух случаях, которые не встречаются в
легитимных SMS:

1. `asks_code` — просьба передать код, пароль, CVV или данные карты
   (банки и операторы никогда об этом не просят);
2. `money_transfer` вместе с `block_threat`, `prize` или `urgency` —
   просьба перевести/оплатить деньги под предлогом угрозы, выигрыша или
   срочности.

Так же, как белый список доменов, это экспертное знание, которое из 200
обучающих SMS не выучить. Ложных срабатываний правило не даёт ни на одном
наборе (train, dev, тесты, все внешние наборы). Сработавшее правило
идёт первой причиной и первым советом в ответе.

## Метрики

| Набор | Accuracy | Precision (fraud) | Recall (fraud) |
|---|---:|---:|---:|
| train (`sms_train.csv`, 200 примеров) | 1.000 | 1.000 | 1.000 |
| dev (`sms_dev.csv`, 40 примеров) | 1.000 | 1.000 | 1.000 |
| dev, только обфусцированные (8 из 40) | 1.000 | — | — |
| новые формулировки (`tests/test_robustness.py`, 30 SMS) | 1.000 | 1.000 | 1.000 |
| языковые варианты (`tests/test_robustness.py`, 31 SMS) | 1.000 | 1.000 | 1.000 |
| внешний набор `sms_phishing_test_120.csv` (120 SMS) | 0.983 | 1.000 | 0.967 |
| внешний набор `sms_phishing_test_150.csv` (140 SMS) | 1.000 | 1.000 | 1.000 |
| внешний набор `sms_phishing_test_2.csv` (159 SMS) | 0.899 | 1.000 | 0.800 |

Метрики посчитаны для итогового варианта: модель + правила.

Ошибок на train и dev нет. Третий набор — 30 SMS, написанных вручную
с темами, транслитом и обфускацией, которых нет в данных (кэшбэк,
пошлина, «продиктуйте CVV», `utup aldynyz`, `за-бло-ки`, `0555-12-34-56`).
Четвёртый — 31 SMS на разных вариантах языка: кыргызский без раскладки
(`картаныз боготтолду`), латиница с `ö/ü/ŋ`, смешанные RU-KG
(`ваша карта заблокирована, кодду жибериңиз`), ссылки без `https://`,
несколько английских.

Внешние наборы (`sms_phishing_test_*.csv`) не из архива организаторов.
Словарь расширялся с оглядкой на ошибки в наборах из 120 и 140 SMS,
поэтому оценки на них оптимистичные; набор `sms_phishing_test_2.csv`
появился после этого, и словарь под него не подбирался — правила
подняли на нём accuracy с 0.723 до 0.899. В наборе из 140 SMS есть
настоящие домены банков (`megacom.kg`, `optima24.kg`, `bakai.kg`) — они
добавлены в белый список, иначе считались подделкой бренда; фишинговые
ссылки там в зонах `.xyz`, `.top`, `.info` — такие зоны теперь считаются
подозрительными; сценарий «с вашего счёта списывают деньги — пришлите
код, чтобы отменить» («алынууда», «жокко чыгаруу», «кирүү аракети»)
добавлен в угрозы. Набор из 120 SMS
устроен иначе: в мошеннических SMS почти нет номеров и
ссылок, только «повод + просьба» («Банк обнаружил проблему, переведите
деньги на безопасный счёт»). До доработки словаря на нём было
accuracy 0.633 / recall 0.267.

**Ограничение.** Оставшиеся ошибки — SMS, где словарь не узнал повод
или просьбу: «посылкаңыз кармалды», «эсебиңиз тоңдурулат», «защищенный
кошелек», «частная карта». Ложных `high` нет ни на одном наборе.

## Сравнение методов

| Вариант | dev Acc / Recall | 61 новое SMS: Acc / P / R | внешние 120: Acc / P / R | внешние 140: Acc / P / R |
|---|---:|---:|---:|---:|
| только 8 обязательных по ТЗ (C=30) | 0.950 / 0.900 | 0.869 / 0.895 / 0.895 | 0.983 / 1.000 / 0.967 | 0.964 / 0.945 / 0.986 |
| 13 (8 + 5 дополнительных) | 1.000 / 1.000 | 0.967 / 1.000 / 0.947 | 0.833 / 1.000 / 0.667 | 0.986 / 1.000 / 0.971 |
| 14 (+ `action_request`), без правил | **1.000 / 1.000** | **0.984 / 1.000 / 0.974** | 0.858 / 1.000 / 0.717 | **1.000 / 1.000 / 1.000** |
| 14, обучение на `sms_train_augmented_2.csv` (C=3) | 1.000 / 1.000 | 0.984 / 1.000 / 0.974 | 0.842 / 1.000 / 0.683 | 0.993 / 1.000 / 0.986 |
| **14 + правила (`rules.py`)** — итоговая | **1.000 / 1.000** | **1.000 / 1.000 / 1.000** | **0.983 / 1.000 / 0.967** | **1.000 / 1.000 / 1.000** |

Все строки, кроме четвёртой, обучены на `sms_train.csv` (200 SMS).
Четвёртая — на `sms_train_augmented_2.csv`: те же 200 SMS плюс по две обфусцированные
копии каждого. Аугментация ничего не даёт: обфускацию и так снимает
`normalize.py`, а новых видов мошенничества в копиях нет. Поэтому
итоговые веса обучены только на `sms_train.csv`, как требует ТЗ.

Для каждого варианта `C` подбирался одинаково — по accuracy на dev
(правила при подборе не участвуют). Модель на 8 признаках неплохо ловит
SMS без телефонов, но хуже на dev, которому по условиям соответствует
скрытый набор, и даёт ложные срабатывания. Итоговый вариант — 14
признаков + правила: лучший или равный результат на всех наборах и ни
одного ложного срабатывания. На `sms_phishing_test_2.csv` без правил
accuracy 0.723, с правилами — 0.899.

- `fake_brand_domain` и `has_link` вместе отличают фишинговую ссылку от
  обычной (ссылки есть и у легитимных SMS — оператор, банк, доставка);
- `has_phone`/`foreign_phone` ловят случаи без явных слов "перезвоните"
  (например, просто номер для перевода денег);
- `safety_warning` — противовес для легитимных предупреждений
  («не переводите деньги», «сак болуңуз»), где есть те же слова, что и
  в мошеннических SMS;
- `action_request` — любая просьба что-то сделать (см. выше).

## Структура проекта

```
detector/
  config.py      — белый список доменов, бренды, пороги LOW/HIGH
  lexicon.py      — словари корней (RU/KY/транслит), причины, советы
  entities.py     — поиск ссылок/телефонов, проверка белого списка и подделок брендов
  normalize.py    — снятие обфускации
  translit.py     — единое написание ө/ү/ң, транслит корней в латиницу
  features.py     — 14 признаков в фиксированном порядке
  model.py        — предсказание скора, уровень риска, причины
  rules.py        — жёсткие правила поверх модели (просьба кода, деньги + повод)
  check.py        — check(text) + CLI
train.py          — обучение логистической регрессии
evaluate.py        — метрики на размеченном CSV
tests/             — pytest
bot/                — Telegram-бот (бонус)
data/               — данные организаторов (не изменяются)
```
